# ERIN V0.2.0 operations

## Observation and reputation

`general`, `general-chat`, `general-*` and their threads are read-only for ERIN.
Conversation, scheduling, moderation and application-command handlers do not act there;
bot-specific channel overwrites also deny sending, reactions and message management.
Other channel names need explicit configuration in `names.is_passive_general`.
Discord administrator permission can bypass overwrites, so application guards also apply.

New messages only are considered for private gameplay observations; general history is
not copied. Questions, uncertain claims, personal-information flags, bots, webhooks and
NSFW channels are excluded. At most six advice checks per UTC day, two per member,
share the autonomous-research budget. Busy checks skip incoming messages rather than
building an unbounded queue. This is sampled observation, not an exhaustive assessment.
Checks must support the entire claim in the same current gameplay context using an
actual retrieved official source or independent recent community sources.

Automatic recognition requires five distinct corroborated claims across at least three
days in the current season, within 90 days. Repeating one answer or receiving endorsements
does not meet this threshold. An authorized negative review overrides automatic recognition.
Recognition only improves teaching-intent detection; it does not lower fact-checking
thresholds, grant review permissions, or turn preferences into facts.

Private self-reported labels include Raid leader, Incursion leader, PvP/PvE-focused,
Healer/Tank/Sniper main and Experienced player. They require explicit statements such as
`I'm a healer main.` Knowing a raid mechanic does not establish leadership. Peer endorsements
require an unambiguous mention, e.g. `@Member is an experienced player.` They retain the
sponsor's ID and a compact label, not a chat transcript. `/experience-review` is ephemeral
and restricted to the owner and existing authorized reviewers. It permits inspection and
independent verification/revocation with a substantive game-related reason.

Observations are private to ERIN/reviewers, not public rankings. Source edits/deletions
withdraw the corresponding observation or endorsement. Observation retention is 90 days;
only minimal gameplay summaries, evidence URLs, source IDs and hashes are stored. Member
learning opt-out and reset remove their observations, reviews and related endorsements;
private exports include them. No new sensitive profile fields are inferred.

## Intake, awareness and research

`Administration/erin-knowledge` accepts text from authorized reviewers. ERIN corroborates
the complete sanitized submission before automatic reuse. Uncertainty prompts clarification
and the existing claim-review workflow. Direct contrary evidence is explained with the
possibility of missing context; replying with conditions/evidence is an appeal.

Awareness runs every six hours, checks up to eight records each pass, and rotates through
active entries, reviewed claims and loadouts. Individual items are revisited no more than
weekly. Unresolved/contradicted claims go only to the configured creator in DMs, with
deduplicated fingerprints. An unavailable verifier does not trigger an uncertainty flood.
Review replies are recorded privately; a yes/no reply does not itself rewrite knowledge.
Sensitive internal questions route a contact request to the creator, not the member's
original message or any pasted secrets. Display-name claims never establish authority.

The research prompt covers current game changes, Central Park announcements, community
ARG leads, creator reactions and beginner explanations, distinguishing speculation from
confirmed features. The September 11 seed adds four attributed briefings, not an assertion
that every site or entire video has been ingested. Source dates and season scope remain
attached to locally stored evidence.

Important developer announcements are selected from each six-hour research pass for
`division-updates`. Only recent, material, high-confidence official patch/maintenance/
outage/fix/balance/season/DLC notices qualify. Source URLs and publication dates are
included; repeat source/date/type combinations are suppressed. At most four posts per
pass. Allowed mentions are disabled; no @everyone or @here notifications. The exact
`TheDivisionGame` X status route is first-party, not X generally. The configured Ubisoft
Trello board remains scoped; unrelated cards are not trusted.

All autonomous work stops in maintenance mode and uses the existing hard API budget and
member-answer reserve. These are lifetime recorded spending limits, not a daily refill.
Availability depends on the desktop/Docker running, provider access and remaining budget.

## Rotations and media

The scheduler wakes every five minutes to detect 08:00 UTC daily resets. Direct sources
refresh every fifteen minutes during the following six hours, normally hourly. Missing
web reports retry at most every 45 minutes during that morning, normally every six hours;
failed attempts also advance the retry clock. Exact values remain dependent on dated
available evidence: this cannot guarantee unpublished or inaccessible live game state.

Loadouts include individual text posts, forum/text-thread replies and archived forum
threads, preserving each message author's ID and link. Source fingerprints avoid repeated
visual spending. A screenshot gets a full view plus four overlapping crops; transcription
is still unverified community data. Old source dates remain historical, not relabeled live.

Videos use up to 18 high-resolution sampled frames inside a maximum 45-second window.
Longer files default to the first 45 seconds; explicit ranges such as `1:10-1:40` or
`10 to 40 seconds` select another window. Upload cap stays 50 MB; screenshots 20 MB.
FFmpeg/FFprobe permit local-file/pipe protocols only. Temporary uploads and frames are
discarded, including on failures. No audio analysis, hidden stats, unreadable text or
unsampled frames are asserted as observed. Incomplete model responses are withheld.

## Deployment

Update 37 is V0.2.0. Migrations 0006 and 0007 allow multiple loadout messages per thread
and add private reputation storage. Back up PostgreSQL and runtime state before upgrading.
Downgrade requires restoring that backup rather than discarding member data. Public notes
contain detailed community changes; administrative-only automatic deployments are logged
without creating an empty public announcement.

### September 11 deployment verification

The final Docker image passed 351 tests (including PostgreSQL integration and real
FFmpeg decoding); Ruff and mypy passed. Migrations were exercised both on an empty
test database and a restored copy of the live 0005 database. The startup seed was
also applied twice to that restored copy: four additions, then zero duplicates.
Existing exact-URL source metadata is reused without overwriting its trust/history;
incompatible source identities are flagged instead of preventing bot startup.

Live verification confirmed V0.2.0, schema 0007, all four new research briefings,
healthy PostgreSQL/bot, Update 37 published, private knowledge intake, read-only
developer updates, and bot send denial in general chat. The pre-deployment backup is
under the Git-ignored `backups/v020-20260911/` directory (database plus runtime).

The live full paid sweep was budget-blocked: approximately $19.53 was recorded before
this deployment against a $25 lifetime hard limit with $5 reserved for member answers.
Limits were not raised. Direct Escalation/vendor collection still works. The live
rotation check remained partial for DC/NYC/Brooklyn targeted loot, invaded missions,
Descent pool, DZ mode, free Classified Assignment and Legendary project. No fabricated
values were substituted. Continuing paid background research requires an authorized
budget change; source availability remains a separate constraint.
